# 第三阶段：评估与迭代

这一层不是继续堆技巧，而是把企业版 skill 变成可以持续验证和优化的系统。

## 目标

第三阶段主要验证四件事：
1. 路由是否稳定
2. 六类内容是否都能产出合格样稿
3. 不同增强模块是否真的提升效果
4. 哪些题适合继续沉淀成固定规则

## 推荐评估顺序

### 1. 先跑固定测试题
优先使用 `test_prompts.json` 中的测试题，保证每次迭代比较的是同一批任务。

### 2. 每题至少检查三层结果
- 路由层：内容类型、传播目标、是否需要资料蒸馏是否判断正确
- 成稿层：标题、开头、正文结构、结尾是否达标
- 增强层：名言、桥段转述、文学意象等模块是否真的贴题、自然

### 3. 先脚本打底，再人工判断
先用：
- `scripts/build_topic_brief.py`
- `scripts/assemble_article_outline.py`
- `scripts/score_article_checklist.py`
- `scripts/build_quote_support.py`
- `scripts/build_scene_support.py`

脚本负责给出中间层和基础分数。

再用人工评审判断：
- 自然度
- 传播冲动
- 贴题程度
- 是否值得转发/收藏

### 4. 每轮至少覆盖六类内容
建议一轮至少覆盖：
- 情感共鸣型
- 知识解释型
- 热点评论型
- 职场成长型
- 搞钱/副业型
- 自媒体复盘型

其中热点评论型要单独加压测试，不能只象征性覆盖。至少应包含下面几种热点方向：
- 新闻热点
- AI 相关热点
- 情感相关社会议题
- 国家大事或公共议题

### 5. 热点要分两层评估
热点类不要只看成稿，还要看两种能力：
- 跟进能力：能不能快速识别事件价值、搜集资料、提炼角度
- 输出能力：能不能把热点翻译成普通人愿意转发的观点和文章结构

如果只评正文，不评资料蒸馏和角度判断，就很容易误判热点能力。

### 6. 记录结论，而不是只记录分数
每轮评估结束后，至少写清：
- 哪一类最稳
- 哪一类最容易写虚
- 哪个模块最值得继续扩库
- 哪些失败案例暴露了路由问题而不是文风问题
- 哪类热点最值得优先跟进
- 哪类热点最容易写成空泛追热点

### 7. 热点专项提醒
热点内容对流量非常重要，但也是最容易失真的一类。评估热点时，必须同时检查：
- 时效性够不够
- 资料基础够不够
- 观点是不是只在复述舆论
- 有没有把热点翻译成“和普通人有关”的判断
- 标题是不是借热点硬拉，而正文承接不住

热点类如果要做企业化复用，资料蒸馏能力和角度判断能力要优先于文风。 

## 本目录结构

- `test_prompts.json`：固定测试题库
- `review_template.md`：单篇样稿评审模板
- `iteration_log.md`：每一轮迭代记录模板

## 最低执行标准

如果要说“第三阶段已经开始”，至少要做到：
1. 有固定测试题
2. 有统一评审模板
3. 有每轮迭代记录
4. 每轮能横向比较，而不是只看单篇感觉

## 最后提醒

第三阶段的关键不是证明 skill 偶尔能写得好，而是让它在反复测试后，越来越知道：什么题该怎么写，什么模块该不该上。
